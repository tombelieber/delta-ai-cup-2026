# Starter Pack Sandbox setup

This candidate implements USD5 once for +100 history imports and +20 bounded learning sessions. It is not enabled by a Stripe MCP connection alone. No live payment mode is implemented.

1. In the selected vic-ai-mvp Sandbox, create an application-specific Restricted API key. Intended scopes are Checkout Session creation/read and PaymentIntent read/capture/cancel, plus current-account/balance reads for merchant/mode verification. Inline price/product creation and expanded price/product reads also need the corresponding permissions. Verify the actual restricted key against the adapter; do not grant unrelated resource access merely to suppress an error.
2. Store that key and the endpoint signing secret in private Secret Manager versions referenced by the Cloud Run runtime. Never place them in Git, build arguments, frontend bundles, URLs, logs or chat. Keep existing Gemini/signing secrets and the USD10 project ledger unchanged.
3. Runtime configuration: `DELTA_STRIPE_ENABLED=sandbox`, `DELTA_STRIPE_ACCOUNT_ID` for the selected Sandbox, `DELTA_STRIPE_RESTRICTED_KEY`, `DELTA_STRIPE_WEBHOOK_SECRET`, and comma-separated verified `DELTA_STRIPE_TEST_UIDS`. Empty or invalid configuration disables purchases. The existing exact `STUDY_ORIGIN`, Google authentication and durable project-budget configuration remain mandatory. The expected Sandbox account is pinned in the adapter.
4. Register the exact deployed `/api/billing/stripe-webhook` endpoint for the Checkout completed/expired/async-success, PaymentIntent capturable/succeeded/canceled/payment-failed, charge-refunded and dispute-created/funds-withdrawn events handled in `server/billing/service.mjs`. The signing secret must match that endpoint and environment. Authenticate events over raw bytes. Capture and fulfilment stay on the server; success URL parameters grant nothing.
5. On the exact candidate, use an allowed Google test account and Stripe test card. Verify the return page's **Check this purchase**, signed event delivery, one grant of 100/20, zero-free-credit paid use, a real PPTX, duplicate/reordered event, cancellation/decline and capacity exhaustion. Check numeric capacity/actual usage without retaining private request bodies. Missing proof keeps the candidate unpromoted.

Paid recovery content is retained encrypted beyond seven days under the owner-approved policy, separately from numeric accounting. It is not a Google Drive integration. The account library is still browser-local; a full cross-device cloud-library UI is outside this payment increment. Back up the stable encryption/signing secret using the operator's existing secret process; changing it without migration would invalidate saved capabilities and keyed identities.

See [local verification and screenshots](verification/starter-pack-payments.md) for tested boundaries and known gaps. Restrict Sandbox sales to the named test users: publicly usable test cards must not unlock real AI capacity for arbitrary accounts. Public users retain the existing free allowance and saved-content paths.
