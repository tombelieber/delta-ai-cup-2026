# Starter Pack operator setup

The pack is a one-time US$5 purchase for 100 additional distinct-video imports and 20 bounded learning sessions. The current storefront uses Delta's independent LIVE account; the two earlier Sandboxes are retained only for their existing receipts. See [current payment qualification and contract](submission/payments.md). Connecting Stripe MCP does not configure the application runtime.

1. Use an application-specific Restricted API key for the exact Delta merchant and mode. Required resources are current-account and balance reads, Checkout Session creation/read, PaymentIntent read/capture/cancel, Charges read, and the inline price/product creation and expanded reads used by the adapter. Do not grant unrelated resource access to suppress an error. Never reuse another product's merchant merely because it shares a legal entity.
2. Store the key and its own destination signing secret in explicit private Secret Manager versions. Never place values in Git, build arguments, frontend bundles, URLs, logs, screenshots or chat. Preserve existing Gemini, encryption/signing secrets and the US$10 project ledger. API key prefixes must match the mode; actual account/balance reads must match the intended merchant. LIVE readiness also requires charging and payouts enabled.
3. Configure `DELTA_STRIPE_ENABLED` as `sandbox` or `live`, the exact `DELTA_STRIPE_ACCOUNT_ID`, `DELTA_STRIPE_RESTRICTED_KEY`, `DELTA_STRIPE_WEBHOOK_SECRET` and `DELTA_STRIPE_SALES_PAUSED`. Sandbox additionally requires bounded verified `DELTA_STRIPE_TEST_UIDS`; that list never limits LIVE sales. Keep the exact `STUDY_ORIGIN`, Google authentication and durable budget configuration. Preserve older purchases through `DELTA_STRIPE_LEGACY_*` and, when needed, sandbox-only `DELTA_STRIPE_VERIFICATION_*`; the three targets must be distinct. Move a Sandbox from current to retained configuration atomically when switching the storefront to LIVE.
4. Register the canonical `/api/billing/stripe-webhook` destination for the ten Checkout, PaymentIntent, refund and dispute events handled in `server/billing/service.mjs`. Direct-account LIVE and Sandbox destinations may use the same URL, but each has its own signing secret. Check the destination account, mode, URL, event selection, API version and actual delivery result before changing a secret reference. Authenticate raw bytes; a return URL grants nothing.
5. Qualify the exact candidate with an allowed Sandbox account and official test cards: cancel/resume, decline, successful capture, one 100/20 grant, repeated reconciliation, refund withdrawal and preserved saved work. Separate fixture security/capacity tests from actual provider results. For LIVE, verify configuration and unpaid/expired-order handling without a real-card test. Actual live capture and grant can only be observed during a legitimate purchase; retain the order correlation privately and never manufacture a self-charge or an automatic refund to claim qualification. [Stripe prohibits testing in live mode with real payment details](https://docs.stripe.com/testing).

To pause new sales, set `DELTA_STRIPE_SALES_PAUSED=true` while preserving the deployed payment-capable image, merchant, test-user allowlist and pinned secret versions. New Checkout creation stops and the purchase CTA is hidden; signed webhooks, existing-order reconciliation and previously granted entitlements remain available. Disabling `DELTA_STRIPE_ENABLED` or rolling back to an image without payment routes is not a safe recovery for in-flight purchases. Resume by setting the pause flag to `false` after qualification.

Paid recovery content is retained encrypted beyond seven days under the owner-approved policy, separately from numeric accounting. It is not a Google Drive integration. The account library is still browser-local; a full cross-device cloud-library UI is outside this payment increment. Back up the stable encryption/signing secret using the operator's existing secret process; changing it without migration would invalidate saved capabilities and keyed identities.

Restrict Sandbox sales to the named test users: publicly usable test cards must not unlock real AI capacity for arbitrary accounts. Public users retain the existing free allowance and saved-content paths. The [payment contract](submission/payments.md) distinguishes actual Sandbox proof, LIVE configuration/delivery evidence and still-unobserved live settlement.


### Web Map verification gate

Run `pnpm test` (server, extension, Web Map adapter and packaging tests), then `pnpm build` and `pnpm build:extension` before preparing a release candidate. `test:server` alone does not exercise the website Map adapter.

Website imports register selected video IDs against the authenticated import allowance before committing new local metadata. Analyze also registers older local records before classification. Metadata files remain limited to 100 records per import; the local accumulated library uses the existing server entitlement ceiling of 3,210 records. A purchased account can explicitly select its Starter Pack classification allocation without spending a learning session. Account changes and failed admission must preserve previous local records.
